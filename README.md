# pi-quiet-tui

Quiet live-then-collapse rendering for the [pi](https://github.com/badlogic/pi-mono) coding agent. Load the extension and the style is on: no extra command, no toggle.

## What you see

- Weight and accent carry the hierarchy: the `◆` marker and the action word (`Run`, `Read`, `Listed`, `Edit`, `Write`, `Thought`) are accented and bold, counts and paths are bold, and everything else in the row — descriptions, merge nouns, command text, the `for 1.2s` clocks — stays in the theme's `dim` color. A `+12` / `−3` count pair uses pi's `toolDiffAdded` / `toolDiffRemoved` colors, so an addition and a deletion never look alike. A failed row keeps the theme's `error` color, with the marker, the tool name and the `exit N` code bold. Nothing else is decorated; the raw command text is never accented.
- Thinking streams inline in the transcript under an accented `◆ Thinking` header, as a live line that carries a token counter and a clock: `◆ Thinking 1,234 tokens for 1.2s`. The thinking text itself is not drawn while it arrives, so the block is exactly one line tall and the transcript below it never moves — the clock and the count only grow wider, they never add a row. When the assistant message is final the line collapses in place to `◆ Thought 1,234 tokens for 1.8s` (the count bold, the clock dim). The answer that follows starts on the next line, with no blank between. Thinking from a resumed session keeps the count but has no duration to show: `◆ Thought 1,234 tokens`. `Ctrl+O` hands the thinking text back to pi, so the block expands in place to the full reasoning. (Needs pi’s **Hide thinking** off — with it on, pi draws its own collapsed label and the transformer never runs; the extension warns once per session.)
- Inspect tools (`read`, `ls`, `grep`, `find`) merge into one diamond line after they finish. `read` names the files it touched, relative to the session, up to two of them followed by a `+N` for the rest, and the other kinds count: `Read src/summaries.ts, test/emphasis.test.ts +3, Listed 3 dirs, Searched 15 patterns`.
- Each `bash` call stays its own row, titled with **what the command does**, not the raw command text: the model's own one-line `description` when it supplies one (`◆ Run 检查已装扩展`), otherwise a heuristic summary of the command (`◆ Run Listed ~/.pi/agent; Searched 'mcpServers' in src`). Commands the heuristics cannot classify fall back to the compacted literal command. While the command runs the header carries a live clock that ticks once a second (`◆ Run 检查已装扩展 for 2.1s`), and the row is **that header alone** — no output block, so its height cannot change between the running and the settled view. On exit the verb turns past tense and the clock settles (`◆ Ran 检查已装扩展 for 2.4s`). `Ctrl+O` always shows the full, untruncated command plus its full output — including while the command is still running, because that is where the live output lives.
- `edit` and `write` show only the size of the change by default, and their header carries it while the model is still streaming: `◆ Write src/a.ts  128 lines` counts the content as it arrives, and `◆ Edit src/a.ts  −3 +12` totals the lines each replacement takes out and puts back, the removed count in the theme's `toolDiffRemoved` color and the added one in `toolDiffAdded`. The counts stay on the settled header, and the unified diff is the detail: `Ctrl+O` expands the row to the diff, with the same header above it.
- The `ask_user_question` questionnaire is one line too, even though the questionnaire itself is drawn by another package: `◆ Asking UI 框架, 补丁范围` while it waits for you, `◆ Asked UI 框架, 补丁范围` once answered (`declined` when you press Esc), and `Ctrl+O` expands to one `"<chip>"="<answer>"` line per question plus your notes. The questionnaire overlay you answer in is untouched.
- Rows and assistant blocks sit directly on top of each other: the blank line pi reserves above a self-rendered tool row and above an assistant block (`◆ Thinking` / `◆ Thought`, reply text) is removed, so a turn reads as one tight stack — and inside an answer there is no blank at all, including the one pi puts between the `◆ Thought` label and the text that follows it. Paragraph breaks in the answer itself are pi's Markdown and stay. The blank line around your own prompt is pi's user-message padding, and it is the turn boundary.
- Your own turn is anchored by one accented `❯` on its first line — the counterweight to the background band the quiet theme removes, drawn from the same accent/weight slots as the `◆` rows rather than from a fill. It costs nothing: the glyph is paid for by the prompt's own left padding, so the turn keeps its width, its line count, and the click coordinates of everything around it, and the rest of the prompt stays exactly as pi rendered it. A turn that has produced no output yet — an aborted one, for instance — gets the marker the moment you submit. The blank line above and below a prompt is still the turn boundary.
- User messages, tool rows, and the composer have no filled color bands. The composer is pi's editor with dim top/bottom rules and nothing else: no prompt prefix, and no rewriting of the lines pi renders — the `↑ N more` scroll indicators, the working-status text in the top rule, and the autocomplete list's own `→` marker all stay as they are.

Tools **this extension does not register** get the same `◆` row. The FFF tools are titled like the inspect rows they mirror (`◆ ffgrep /useEffect/ in src`); any other tool is titled with its name and its most readable argument (`◆ Agent Review changes` — the model's own `description` when it supplies one, otherwise `prompt`/`objective`/`command`/…, cut to one line) and shows its full text output on `Ctrl+O`. While a tool quiet knows nothing about is still running, its row keeps its own live rendering and collapses to the `◆` line once it settles, so no live progress a package draws for itself is thrown away — except for the FFF tools, whose own arguments are known and whose running row is therefore the same one-line `◆` header every other quiet row is. A row that carries images is left alone entirely. Only the background band is removed from rows this extension cannot title.

## Install

From this directory:

```bash
pi -e ./extensions/index.ts
```

Or install as a pi package:

```bash
pi install ./
```

Or copy into the auto-load location:

```bash
cp -R . ~/.pi/agent/extensions/quiet-tui
```

Unloading the extension (omit `-e`, `pi remove`, or delete the copy) restores pi’s default TUI.

## Notes

- Emphasis is a pure string transform over the one-line rows (`src/emphasis.ts`), applied at the two places every row passes through: `headerLine` for tool rows, and the thinking Markdown transformer for `◆ Thinking` / `◆ Thought`. The formatters in `src/summaries.ts` still return plain text and are still asserted as text.
- `edit` and `write` split one row across pi's two render slots: `renderCall` draws the header (with live line counts while the arguments stream), and `renderResult` adds only the body — nothing when collapsed, the unified diff when expanded. pi stacks the call and result components instead of replacing the call one, so the header is never repeated. The `write` counter is incremental — it counts only the delta since the last render — because the model streams a file body token by token and a full recount per delta would be quadratic in the file size.
- A `Run` row's clock follows pi's own shell renderer: it stamps `startedAt` from the render context and repaints the transcript with `setInterval(ctx.invalidate, 1000)`, then clears the timer the moment the call settles and takes pi's recorded `durationMs` when there is one. An expanded running call draws every line it has printed instead of the five-line tail.
- The questionnaire row is rewritten without owning its tool. pi gives a tool name to the **first** registrant only (`ExtensionRunner.getAllRegisteredTools`), and the questionnaire package loads before this one, so `ask_user_question` cannot be re-registered with a quiet `renderCall`/`renderResult`. The row is therefore substituted inside the same transcript-container patch that removes the blank lines (`src/questionnaire.ts`), keyed off the row component's own fields (`toolName`, `args`, `result`, `isPartial`, `expanded`): a pi release that renames them makes the substitution decline and the row returns to pi's box instead of breaking. The row also ends an inspect burst, so reads on either side of a questionnaire do not merge onto one line. Every other tool this extension does not register is a foreign row to the same patch and is substituted the same way (`src/rows.ts`) — the FFF tools (`ffgrep`, `fffind`, `fff-multi-grep`) with a title of their own argument shape, every other tool with its name plus one readable argument. Those rows key off the same fields, plus `isPartial` to leave a running tool's own live rendering in place and `imageComponents`/`result.content` to leave an image row untouched.
- The `bash` tool registers one extra optional parameter, `description` (prompt guideline: one line, ≤ 8 words, in the user's language). It is display metadata only — pi and the shell ignore it, and the header falls back to the heuristic summary when it is missing. The heuristic phrases run summaries like the merged inspect lines (`Listed …`, `Searched … in …`, `Ran tests`, `git status`), drops `cd`/`echo`/redirection noise, and shortens paths under `$HOME` to `~`.

- Thinking needs pi's **Hide thinking** off (`Ctrl+T`): with thinking hidden pi renders the collapsed label instead of the block, so the live counter has no inline slot. The extension warns once per session when it is hidden; the label itself carries the `◆` marker and is accented the same way.
- `Ctrl+O` expands the thinking text by making the Markdown transformer return the run's raw Markdown. The transformer cannot see the toggle itself, and an unchanged `Markdown` child would keep its cached label lines, so the transcript patch watches each assistant message for a change of `ui.getToolsExpanded()` and rebuilds the message when it flips; the rebuild re-runs the transformer with the new state. A pi release that renames `invalidate` leaves the label in place instead of throwing. When pi is hiding thinking (`Ctrl+T`), that path is not used — pi draws its own label and no transformer runs.
- The thinking count is an **estimate**: `src/thinking.ts` divides the run's character count by 4, the same divisor pi uses for its own context estimate (`estimateTokens2` in the compaction helpers), so the number on screen is counted the way pi counts the thinking it replays. It is not provider usage — no usage figures reach an extension while a message is still streaming; pi folds them in only when the stream ends. The estimator reads the accumulated run text, which is the same trimmed, blank-line-joined string pi hands to the transformer for the block. The live ` for 1.2s` clock comes from the same source as the run clock: the controller stamps `startedAt` on the first thinking token and the seconds advance as the block is re-rendered for each arriving token.
- The thinking labels are styled by putting ANSI codes into the Markdown the transformer returns, which pi only *displays* — the message in the session and in the model context keeps the plain `◆ Thinking 1,234 tokens for 1.2s` / `◆ Thought 1,234 tokens for 0.4s` text. A trailing ` for 0.4s` (after the count) re-opens the thinking color on purpose: pi wraps each rendered line in `fg("thinkingText")`, and a nested color span ends with a foreground reset, so text after the accented span would otherwise fall back to the terminal's default foreground.
- The theme patch installs a patched copy of the **active** theme, so your accents and syntax colors stay. Switching themes afterwards (`/theme`) replaces that instance and the patches are gone until the next start.
- Pi warns when an extension overrides built-in tools. That is expected.
- User-typed `!` / `!!` shell still uses pi’s bordered runner. Agent `bash` uses quiet rendering.
- Print and RPC modes load the extension without TUI calls.
- Both TUI modes are covered. Fullscreen wraps the transcript in pi's `ScrollView`/`VStack` viewport, but that viewport's child is the same `Container` the main screen mounts, `ScrollView` extends `Container` and pushes its child into `.children`, and `Container.render` records the `mouseLayout` the patch repairs either way — so the transcript walk, the blank-line tightening (at both levels), the questionnaire row substitution, and click routing all behave the same. `test/spacing.test.ts` builds that real viewport (`createChatViewport`'s shape) to hold it.
- The streamed thinking block is a **single line**, so there is no height to keep: the live view is only the `◆ Thinking` header plus the count, which fits in ~26 columns even at a million tokens — far under the width any usable transcript renders at. Earlier revisions streamed a padded three-line tail of the thinking text; dropping the text is what made the fixed-height machinery unnecessary.
- A running row draws no output at all, so its height is the same before and after it settles and the transcript below it never moves. That is a deliberate reversal of the earlier fixed-height tail (`TailViewport`, since removed): pinning the tail kept the height stable *while* output arrived, but the block still appeared when the first output did and collapsed when the call settled — two moves of its own height per call, which pi answers by repainting: `TuiMainScreen` runs a full `fullRender(true)` (`ESC[2J ESC[H ESC[3J`, screen **and** scrollback) when the content it is drawing shrinks below what it has already drawn, a path its own settings call "Clear on shrink (may cause flicker)", and in fullscreen mode the same shrink moves the whole `ScrollView` viewport. The output is not lost: it is the expanded view, and for a running call it is everything printed so far.
- Pi pads its transcript with blank lines: `ToolExecutionComponent.render` returns `["", ...content]` for every self-shell tool row, `AssistantMessageComponent` puts a `Spacer` above every assistant block, and its `Spacer(1)` separates turns — a turn of one-line rows spends as much height on blanks as on content. There is no hook for them, so the extension patches the live transcript container (`src/spacing.ts`): the chat container is found by walking the component tree the editor factory's TUI proxy exposes (`ctx.ui` itself does not), and its `render` is replaced with one that drops the leading blank from agent-output children, drops all-blank `Spacer` children outright, then repairs the heights in `mouseLayout` so click routing and scrolling keep matching the shorter output. An assistant message holds one of those blanks one level deeper than the transcript — `AssistantMessageComponent.updateContent` adds a `Spacer(1)` to its own `contentContainer` between a thinking run and the visible content after it (the `◆ Thought` label and the answer, in the common case) — so the same pass is installed on each message's `contentContainer` before it renders, and the answer ends up blank-free while the paragraph breaks pi's Markdown draws inside a single child stay. Escape prefixes travel with the line that is kept, because an assistant message's first line carries pi's OSC 133 zone marker. This keys off pi-internal component shapes (`toolCallId`/`updateResult`, `contentContainer`/`updateContent`), so a pi release that renames them silently restores the spacers instead of failing. It applies to every tool row, including ones other extensions register; user messages and unknown blocks keep pi's spacing. A substituted questionnaire row is wrapped to the container width here too, because it no longer passes through the `Text` component that would have wrapped it.
